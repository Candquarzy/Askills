# Askills 实现方案

更新日期：2026-10-18。状态：**P1–P3 核心流程已实现，处于 Windows 开发预览验收**。

本文保留完整目标设计；“当前实现记录”说明本轮实际交付及与目标设计的差异。后文中的全部验收条件并不代表已经满足。
实际操作步骤见 [用户指南](user-guide.md)，测试证据见 [验证记录](validation.md)。
项目按用户选择采用 MIT 协议；第三方 skills 保留各自协议，不因进入 Askills 而变为 MIT。

## 当前实现记录

已实现三个可串联的流程：本地完整目录导入和版本阅读 → 项目登记/扫描/固定版本部署 → GitHub 公共来源下载、版本差异及逐项目升级。前端组件按 `features` 分组，Rust 按 `commands/domain/services/storage/platform/sources/adapters` 分层，业务测试不需要启动 WebView。

### 数据与文件

- SQLite schema 1，WAL、外键、单应用进程锁；本地库另有独占锁，项目写入使用项目锁。技能、revision、项目以带类型 JSON 持久化，关系键和来源唯一键由 SQL 约束；部署、计划和恢复日志使用独立表。
- 默认库为应用本地数据目录下的 `library/`，可在空库时选择专用目录。快照布局为 `skills/<uuid>/revisions/<sha256>/`；每技能 manifest 仅保存相对快照路径，可恢复丢失的技能索引。项目与部署索引仍需备份数据库。
- 同一本地路径或同一 GitHub 仓库/子目录属于同一个技能，commit/ref 不作为技能身份；新提交是独立 revision，内容相同可以共享内容快照。跨版本 `name` 变化拒绝导入，重命名迁移尚未提供。
- 原文件不会被移动。预览摘要、复制后摘要和最终读取校验防止来源变化；无引用的孤立快照暂保留，不自动回收。外部损坏 manifest 或丢失快照会阻止库打开并报错，尚无局部损坏隔离界面。
- 库与源目录的链接/重解析点、越界相对引用、设备名、大小写冲突和过量文件被拒绝。当前本地导入上限 4,000 文件、8,000 条目、128 MiB 总内容、单文件 16 MiB、深度 32。

### 命令、部署与恢复

- WebView 只传内部 ID；文件夹必须由 Rust 原生选择器授权。目录选择、导入和 GitHub 候选使用有用途、限量、30 分钟有效期的后端 token；新的目录选择替换上一批未完成目录授权。
- 当前采用单任务 `spawn_blocking` 加互斥状态，原子取消标志可在独立命令中设置。不是完整后台队列：显示阶段文案，尚无百分比进度、任务历史或多任务并行。取消等待当前安全步骤，网络请求最长等待 25 秒超时。
- 每次预览在后端保存计划；应用时再次核对源、项目入口身份和锁文件。自动模式依次尝试 symlink、Windows junction、copy；显式模式失败则报错。
- 先写持久化操作日志，再创建临时入口、换入目标、更新项目锁和数据库。启动时按日志恢复可确认身份的旧状态；遇到未知替换或无法确定归属的临时对象保留文件并提示人工检查。
- `askills.lock.json` 保存可分享的相对目标、摘要、来源和 commit，不保存绝对库路径。尚未实现锁文件跨机重建、批量升级向导、非管理目录接管、完整库迁移和备份/恢复界面。

### 来源与阅读

- 公共 GitHub API 按仓库/ref 解析完整 commit 和 Git tree，再逐文件取 blob 并校验 Git blob SHA-1；本轮未使用 ZIP 归档。禁止重定向、不读取用户凭据、不执行 git 或下载脚本；API 不完整树、链接和子模块均拒绝。
- 完整选定目录上限 1,000 文件、32 MiB、单文件 2 MiB；保留祖先 LICENSE/NOTICE 于 `.askills-source-licenses/`。选定技能之外的巨大仓库或危险条目也可能导致拒绝；候选目录发现不等于已经通过技能内容校验。
- 新版本先加入本地库，不自动替换项目。可比较新增/删除/修改文件及 SKILL.md 两列原文，再手动选择每个要升级的项目。
- 阅读器使用 `react-markdown` + GFM，禁用原始 HTML、图片加载和外部导航；原文模式保留 frontmatter。中文界面已实现，文案全量抽取和自动翻译属于 P4。
- 浏览器 Playwright 测试使用明确的 IPC fixture；Windows 原生窗口、Rust 真实文件系统和显式联网冒烟单独验收。Vitest、Tauri WebDriver 和三平台发行矩阵仍属后续安排。

以下章节描述目标方案和剩余工作；以本节和代码为当前实际行为依据。

## 1. 产品目标与首版边界

Askills 是面向本地开发者的中文桌面 skills 管理器，优先支持 Windows，架构兼容 macOS 和 Linux。
核心流程为：导入或下载 skill → 在统一仓库查看 → 选择项目与目标工具 → 预览文件变更 → 应用 → 检查状态。
中文阅读辅助直接服务于 skill 的理解和选择，不修改 Agent 实际使用的原文。

首版必须覆盖以下场景：

- 把已有 skill 文件夹复制导入统一仓库，保留原文件夹；校验并展示 `SKILL.md`、来源、版本和许可证。
- 手动添加项目或指定扫描根目录，识别项目内现有 skills、实际路径、链接目标和管理状态。
- 给一个或多个项目安装、升级、卸载指定 skill，明确实际影响的工具和文件路径。
- 从 GitHub 公共仓库中的指定目录下载，固定 commit，查看更新差异并回滚。
- 默认中文界面；配置翻译服务后，可自动翻译当前阅读内容并切换原文/中文。
- 无网络、无翻译密钥时，本地浏览和项目管理仍能工作。

首版不包含：运行 skill 脚本、执行其指令、云端账号体系、多人同步、自建 marketplace、任意网页抓取、Agent 会话管理。
工具的插件、MCP、rules 与 skills 有不同生命周期；第一版只处理文件夹型 skills，不把它们混为同一种安装对象。
私有 GitHub 仓库、GitLab 等来源、配置同步和应用自动升级放到后续版本。

## 2. 技术方案与模块边界

采用官方 `create-tauri-app` 的 React + TypeScript 基础工程，前端使用 Vite、pnpm；原生逻辑使用 Rust 和 Tauri 2。
前端负责页面、交互、中文文案与任务状态，Rust 负责文件系统、来源下载、索引、链接、凭据和翻译请求。
Windows 开发环境需要 Rust、Microsoft C++ Build Tools 与 WebView2；本地可启动、Rust 可编译、安装包可生成要分别验收。[Tauri 前置要求](https://v2.tauri.app/start/prerequisites/)

计划在实际需要时引入依赖，避免初始化阶段一次性装入全部技术栈：

- 元数据：SQLite，经 Rust `rusqlite` 访问；开启外键，串行写入，使用迁移版本。
- 网络：Rust `reqwest` + TLS；下载、限速、重试和重定向由后端统一处理。
- 文档：前端 Markdown 渲染与严格清洗；Rust 解析 frontmatter，保留未知字段。
- 文件发现：有边界的递归遍历；`notify` 仅作为变化提示，定期/手动重扫负责校准。
- 内容校验：SHA-256；稳定排序的相对路径、文件类型和文件字节参与目录摘要。
- 凭据：操作系统凭据库；配置和 SQLite 仅保存凭据引用。
- 界面：中文优先，文案资源集中管理，后续加入英文；组件库待页面原型评审后选择。

预计代码边界如下，以下目录不表示本次已建立全部模块：

```text
src/
  app/                  路由、布局、语言与错误边界
  features/             library、projects、sources、translation、settings
  components/           可复用展示和输入组件
  lib/ipc/              Tauri 命令、事件与类型转换
src-tauri/src/
  commands/             只做输入转换、授权边界检查和服务调用
  domain/               Skill、Revision、Project、Binding、Operation
  services/             导入、扫描、安装、升级、恢复、翻译
  adapters/             codex、cursor、claude_code
  storage/              SQLite、迁移、manifest 与内容仓库
  platform/             路径身份、链接、凭据、原生文件对话框
  sources/              GitHubSource 与后续来源适配器
```

业务服务不依赖 WebView，便于在临时目录内完成真实文件系统测试。
IPC 传递项目 ID、revision ID 和操作 ID；前端不得自由拼接任意写入路径。
长任务先返回任务 ID，再通过事件汇报进度；支持取消、失败原因和重试，不阻塞窗口。
命令采用带类型的错误，例如 `PathConflict`、`PermissionDenied`、`SourceUnavailable`、`LocalChangesDetected`。
Tauri 命令和事件只承担进程间通信，不能替代业务授权与数据验证。[Tauri Rust 命令](https://v2.tauri.app/develop/calling-rust/)

## 3. 统一本地仓库与内容生命周期

首次使用允许选择技能库位置，默认由 Tauri 平台路径 API 解析到应用本地数据目录下的 `skills/`。
程序配置、数据库和日志放在应用数据目录；用户选定的技能库可以位于独立磁盘。
不得硬编码用户名、盘符或假定应用数据目录等于用户主目录。

```text
<library-root>/
  library.json                           仓库 UUID、格式版本
  skills/<skill-id>/manifest.json         可恢复的来源与 revision 清单
  skills/<skill-id>/revisions/<hash>/     完整 skill 目录，视为不可变
  local/<skill-id>/                       可选的本地创作副本
  staging/<operation-id>/                 下载/导入中间态
  trash/<operation-id>/                   有保留期限的卸载备份
<app-data>/
  askills.db                             索引、项目、绑定、任务、缓存
  settings.json                          非敏感偏好与技能库位置
  logs/                                  脱敏诊断
```

skill 的唯一身份使用内部 UUID；`name` 是显示/调用标识，不用作唯一主键。
同名但来源不同的 skills 保持独立，并在安装到相同目的目录前显示冲突。
一个 revision 包含完整目录，而非只有 `SKILL.md`，以保存相对引用的 scripts、references 和 assets。
导入时检查 Markdown 可识别的本地相对引用；超出 skill 根目录的引用、缺失附件与脚本中无法静态解析的动态引用分别展示诊断，不能标记为已完整验证。
首版对可识别的越界本地引用阻止“完整导入”，说明缺失位置；不自动跟随 `../` 复制任意文件。
需要引用适配时，先在独立副本中补齐经用户选择的附件并调整引用，保存原提交、补充文件清单与修改 diff，再作为新的本地派生 revision 导入。
后续可把该流程集成到导入向导；来源版本与派生内容摘要保持分离，不能冒充未改动的上游版本。
校验参考 Agent Skills 标准：目录结构、frontmatter 必填字段、命名和长度规则；工具专有字段保留并显示兼容性信息。[Agent Skills 规范](https://agentskills.io/specification)

本地导入采用复制快照，不移动或接管原目录；导入前预览文件数量、大小、目标位置和重复项。
初版对导入内容中的符号链接及其他重解析点采用拒绝策略，说明具体文件，避免无意把库外文件带入仓库。
本地创作副本修改后显式生成新 revision；已安装项目保持原 revision，直到用户选择升级。
不可变是管理器的约束，不保证操作系统禁止外部写入；扫描发现摘要变化就标记损坏/漂移并停止自动覆盖。
技能库迁移先复制与校验，再重新生成受管理链接，失败可恢复；不能直接移动目录后假定链接仍然有效。

## 4. 项目发现与 Agent 适配

### 4.1 项目入口

先做“添加项目文件夹”和“扫描指定目录”，不默认扫描整盘或读取各工具的私有历史数据库。
用户指定扫描根、最大深度与排除项后，识别 Git 工作区及已知技能目录；没有 `.git` 的目录也可手动注册。
Git worktree 的 `.git` 可能是文件，项目根识别必须覆盖；同一仓库的不同 worktree 分别登记。
递归发现跳过 `.git`、`node_modules`、`target`、构建产物、库目录本身，并限制条目数量与耗时。
默认不跟随目录链接，避免循环和越界；已知 skill 入口链接单独解析，记录最终路径与解析错误。
项目路径移动/删除时标记离线，支持重新定位；不得把“路径不可达”当成自动删除绑定的依据。

后续可提供“从工具导入最近项目”，但需要独立适配、用户选择、版本兼容测试；不能把未公开配置文件当稳定 API。

### 4.2 当前文档支持的路径

以下路径于 2026-10-18 核验；适配器需记录规则版本与文档链接，并显示“已识别”“待验证”两种状态。

- **Codex**：项目 `.agents/skills/`，从当前工作目录向上直到仓库根查找；用户级 `~/.agents/skills/`。官方明确支持 skill 文件夹符号链接。系统/管理员目录仅展示，不接管。[OpenAI 官方 skills 文档](https://learn.chatgpt.com/docs/build-skills)
- **Cursor**：项目 `.agents/skills/`、`.cursor/skills/`；用户级 `~/.agents/skills/`、`~/.cursor/skills/`；还兼容 `.claude/skills/` 与 `.codex/skills/` 等路径。嵌套项目 skills 的作用域与所在子目录相关。[Cursor 官方 skills 文档](https://cursor.com/docs/skills)
- **Claude Code**：项目 `.claude/skills/<name>/SKILL.md`、用户级 `~/.claude/skills/<name>/SKILL.md`，另有嵌套目录、附加目录、插件和企业来源；首版只写普通项目路径。[Claude Code 官方 skills 文档](https://code.claude.com/docs/en/skills)

新建 Codex 绑定默认使用 `.agents/skills/`；`.codex/skills/` 只作为已有/兼容候选扫描，不能宣称它是当前统一官方项目入口。
Cursor 默认使用 `.cursor/skills/`；Claude Code 适配放在第二个适配阶段，首个可用版本先保证 Codex 和 Cursor。
插件管理目录和内置技能保持只读；应用管理普通项目 skills，不替代 Agent 自身的插件管理。

**工具隔离不是天然成立的。** Cursor 会读取共享及兼容路径，因此“安装给 Codex”也可能被 Cursor 发现。
界面必须展示“安装路径”和“可能读取此路径的工具”；首版不承诺任意工具之间完全隔离。
同一物理入口只创建一个实际部署记录，可关联多个读取工具，避免对共享路径重复写入或重复卸载。
嵌套项目需展示根目录、作用目录、继承来源；“当前可见 skills”由适配器计算，不仅列出根目录文件。

### 4.3 适配器契约

每个适配器提供：路径候选、作用域推导、兼容规则、安装目标建议、刷新提示和能力探测结果。
统一扫描结果包含：入口路径、解析后路径、来源作用域、skill 名称、管理状态、目标工具、诊断列表。
状态至少区分：外部现有、受管理且正常、被修改、链接失效、名称冲突、格式无效、权限不足。
管理器只读展示外部现有目录；要转为受管理状态，须预览导入、备份与替换操作。
首版“卸载”仅影响 Askills 创建的入口，不自动编辑 Agent 全局配置或移除用户既有文件。

## 5. 链接、复制与安装事务

### 5.1 部署模式

默认提供“自动选择”，并允许每个项目固定模式；界面显示最终采用的方式和原因。

1. macOS/Linux：优先目录符号链接，链接到库内固定 revision；工具实测不支持时使用复制。
2. Windows：探测目录符号链接能力；失败时在本地适用文件系统上尝试目录 junction；仍不适用则复制。
3. 网络共享、远程环境、容器、云端 Agent 或计划随 Git 分发的项目：建议复制，并提供显式选择。
4. 不采用硬链接树：它不能直接链接目录，且文件修改会产生共享写入风险。

Windows 符号链接创建能力受系统权限、开发者模式及 API 标志影响，必须实际探测。[Microsoft CreateSymbolicLinkW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createsymboliclinkw)
junction 是目录层面的重解析机制，支持本地卷之间的目标，但不能据此承诺 UNC 路径可用。[Microsoft links and junctions](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions)
探测创建临时入口后立即清理；无权限时降级，不让普通安装依赖管理员启动。
只有单个 skill 子目录被链接，保留项目 skills 根目录及其他已有内容。
链接固定 revision，因此新增库版本不会让所有项目静默升级。
复制模式记录安装时摘要；升级前若目标被编辑，要求保留副本、导入新 revision 或取消，不能直接覆盖。
本地绝对链接不可移植，Git 也不能代替库内容分发；共享项目优先采用复制或依据锁文件重新安装。

### 5.2 安装与恢复协议

SQLite 事务不能原子覆盖文件系统变化，因此需要显式操作日志及可恢复状态机：

1. `planned`：解析真实路径、确认项目范围、检查名称冲突、磁盘空间、目标状态，生成变更预览。
2. `prepared`：持久化操作 ID、原目标摘要/链接身份、期望 revision 和回滚位置，再准备临时入口。
3. `applying`：取得项目级锁，重新核对预览时的条件，备份受管理旧入口，在目标同一父目录完成重命名/切换。
4. `verifying`：检查入口类型、解析目标、内容摘要、`SKILL.md` 可读性，再更新绑定和锁文件。
5. `committed`：记录完成并保留必要备份；失败进入 `rollback_required`，恢复旧入口后记录结果。

不声称多个文件、锁文件和数据库能单一原子提交；程序重启时按日志核对实际磁盘状态再恢复。
准备下载目录可在库内，但项目切换临时项必须位于目标父目录，避免跨卷重命名失效。
遇到 Windows 文件占用时保留原绑定，给出可重试错误；不得先删除旧版本再试着下载新版本。
卸载前使用不跟随链接的元数据检查，验证入口仍由本操作管理；只移除链接本身，不递归删除所指仓库。
复制安装删除前必须核对当前摘要；来源漂移、父目录变为重解析点或计划失效时停止并重新预览。
所有删除和回滚路径都需检查真实父目录、预期对象身份及允许范围；仅字符串前缀检查不足以防止越界。

## 6. 数据模型与可移植清单

SQLite 用于查询和运行状态；文件内容由库内目录承载，manifest 用于恢复来源；项目锁文件描述可重建的期望状态。
数据不是互相随意覆盖：内容摘要验证磁盘，manifest 重建库索引，绑定日志协调运行中状态，锁文件变更需要重新计划应用。

建议的数据实体与关键约束：

- `libraries`：`id`、本机根路径、格式版本、最近校验时间；一个活动库。
- `skills`：`id`、名称、描述、来源类型、标签、许可证摘要、当前推荐 revision；名称允许重复。
- `revisions`：`id`、`skill_id`、完整 commit、来源子路径、内容摘要、库内相对路径、创建时间；同一 skill 的相同来源版本/摘要去重，不合并不同来源的身份。
- `sources`：`id`、provider、规范化仓库 URL、owner/repo、来源等级、凭据引用；不存 token。
- `projects`：`id`、显示名、原始路径、规范化路径、平台文件身份、工作区根、离线状态。
- `project_agents`：`project_id`、adapter、规则版本、作用目录、能力探测结果；多工具可关联同项目。
- `deployments`：`id`、`project_id`、目标相对路径、`revision_id`、模式、入口身份、安装摘要、状态；物理目标唯一。
- `deployment_consumers`：`deployment_id`、adapter；表达一个入口被多个工具读取，不复制实体部署。
- `operations`：操作 ID、阶段、计划摘要、备份位置、错误、起止时间；支持启动恢复和审计。
- `translations`：源内容摘要、目标语言、provider/model、提示词版本、译文、状态、用量；组成缓存键。

所有时间以 UTC 存储并按界面时区显示；路径按平台语义处理，不简单全部转为小写。
Windows 比较考虑路径大小写与文件身份；保留用户原始拼写，支持中文、空格、长路径和不同磁盘。
数据库迁移前创建备份；迁移失败不继续写入；导出配置时排除 token、机器绝对路径与日志正文。

项目锁文件拟用 `askills.lock.json`，本机运行状态留在数据库；格式在 P2 前冻结并给出 JSON Schema。
锁文件仅记录 schemaVersion、skill 来源、完整 commit、本地内容摘要、安装路径和推荐模式。
不把 API 密钥、本机库根路径写入锁文件；没有可获取来源的本地 skill 明示“需要导出包”，不能声称可异机复原。
锁文件与项目入口冲突时生成差异，不自动选择任何一方覆盖。
链接方案可选择在 `.git/info/exclude` 中排除机器入口；不静默改写团队 `.gitignore`，共享复制模式由用户决定是否提交。
后续备份包包含内容、manifest 与许可证，导入时重新校验摘要和路径，凭据单独配置。

## 7. GitHub 下载与来源管理

首个来源只支持 GitHub 公共仓库链接，以及明确的 owner/repo、ref、子目录输入。
入口是精选来源列表和粘贴 URL，不承诺一个未经维护的全网搜索引擎。
一个仓库包含多个 skills 时先展示候选目录，允许选择，避免把整个仓库误识别为一个 skill。
包含斜杠的分支名与目录不能用简单 URL 切分猜测；查询 refs/目录确认，歧义时明确要求选择。

下载步骤为：规范化来源 → 解析 ref 为完整 commit → 读取候选清单 → 用户选择 → 下载该 commit → 校验 → 原子加入库。
API 的 ref 可以指定 branch/tag/commit；实际内容下载必须使用解析后的完整 commit，不依赖可移动的默认分支。[GitHub repository contents API](https://docs.github.com/en/rest/repos/contents)
使用 archive 下载时处理 302，限制跳转域名且不向其他域名转发 Authorization；只提取选中目录。
下载完成后执行与本地导入相同的引用完整性检查；有跨根目录依赖时显示具体缺失引用，按上一节的派生 revision 流程处理，不能悄悄扩大提取范围。
记录仓库 URL、子目录、原始 ref、完整 commit、下载时间和内容摘要；“来源可追溯”不等于“内容安全”。
GitHub star 数和更新时间只作参考，不用作安全认证；来源等级区分官方组织、人工收录和用户自定义。
官方组织身份也需要核对准确仓库及许可证，不能只依据名称相似。

归档处理拒绝 `..`、绝对路径、盘符/UNC、设备文件、符号链接、重复路径、大小写冲突和目录外写入。
限制压缩前后字节、文件数量、单文件大小与压缩比，流式检查实际大小；下载取消后只清理本操作的 staging。
保留上游 LICENSE/NOTICE；子目录无许可证时查仓库许可证并记录来源，无法确定时标明未知，不宣传可再分发。
下载不运行脚本、不执行包安装、不开 Git hooks；skill 指令也不能当作下载器操作指令执行。
限制并发，支持超时、取消、重试、GitHub 速率限制和缓存；错误信息不能打印 token。

更新只检查用户启用的来源；提示新 commit、正文/脚本变化、许可证变化和受影响项目。
下载新 revision 后由用户选择升级哪些项目，旧 revision 保留供回滚；被绑定的 revision 禁止垃圾回收。
私有仓库后续使用最小读取权限与系统凭据库，不默认复用 GitHub CLI 的认证数据。
其他来源扩展统一 `resolve / list_candidates / download / check_update` 接口，各自定义信任和认证规则。

## 8. 中文界面与自动翻译

中文界面与技能翻译分开实现：按钮、错误、状态和设置是人工维护的中文资源；skill 正文翻译是可选服务。
语言默认 `zh-CN`，英文作为后备；保留技术名词、路径、命令和错误码，便于用户排障。
阅读器提供原文、中文、对照三种视图；显示机器翻译标记、来源版本、翻译模型及缓存状态。

首版翻译提供两类用户自选后端，不内置共享密钥：

- OpenAI 兼容接口：配置 base URL、model、密钥引用及超时；以约定的 Chat Completions 子集实现并执行连通性测试。
- Ollama：用户安装并选择本地模型，通过其 `/api/chat` 调用；模型下载与硬件需求由用户自行管理。[Ollama chat API](https://docs.ollama.com/api/chat)

“兼容”不意味着所有服务商字段完全一致；请求参数能力应可配置，不偷偷把配置失败请求转发到其他服务。
外部服务首次启用时说明将发送当前 skill 文本；自动翻译开关默认关闭，由用户打开后按阅读需求自动触发。
Ollama 默认仅接受 loopback 地址；自定义局域网/远端地址作为显式高级设置，不能把所有 HTTP 端点称为本地处理。
远端接口默认 HTTPS；提供者只收到选择的文字，不上传整个项目、脚本附件或本机目录。

翻译前按 Markdown 结构拆分，保护代码块、行内代码、URL、相对链接、frontmatter 键和变量占位符。
先翻译名称说明和 description，再按阅读需要翻译正文；不翻译可执行脚本内容，不改 Agent 的 `SKILL.md`。
译文作为显示层缓存保存，绝不覆盖原文或安装目录；相对资源链接仍相对于原文来源解析。
把待翻译文本作为不可信材料，翻译请求不启用工具，也不能接受材料中“运行命令/上传文件”等指令。
缓存键包括内容摘要、语言、提供者、模型和翻译提示版本；源版本变化自然失效，失败结果不当成功缓存。
支持分块进度、取消、手动重译、429 退避和并发限制；无法可靠估算价格时显示字数/用量而非虚构费用。
断网时展示已有译文和原文；翻译失败只影响当前阅读，不阻断技能安装与项目操作。

## 9. 界面信息架构与核心操作

主导航拟为：技能库、项目、来源、任务记录、设置。首个迭代以可用性为主，不先做复杂仪表盘。
技能库提供搜索、标签、来源/状态过滤、详情、版本、使用项目和安装入口。
项目详情先展示项目路径与检测工具，再展示各作用目录下的已有和可安装 skills。
来源页提供 URL 导入、精选来源、更新检查和来源信任说明；任务页呈现可重试失败及恢复结果。
设置提供库位置、默认部署模式、语言、翻译服务、凭据状态和数据导出。

单项安装流：选 skill → 选项目/作用目录 → 选模式 → 显示路径与工具影响 → 应用 → 校验结果。
批量操作按项目分组、逐项回报成功/失败，不用一个“成功”掩盖部分失败；已成功项目不随其他项目失败而重复写入。
冲突页明确区分同名、已存在目录、外部修改和共享入口；给出取消、改选来源或备份接管等具体选项。
空状态指向“导入本地 skill”或“添加项目”；未实现的入口不伪装成功，也不使用无意义成功提示。
首版包含键盘导航、可见焦点、中文长文本、缩放与高 DPI 检查；所有操作可从任务记录找到结果。

## 10. 安全与数据保护设计

Tauri capability 只授权主窗口实际需要的功能，不给远程内容任何 IPC 权限，不开放任意 shell 执行。
自定义 `invoke_handler` 命令默认可被应用窗口调用，需要显式使用 AppManifest 权限约束并在 Rust 内做范围检查；capability 不会自动限制任意 Rust 文件操作。[Tauri capability 安全边界](https://v2.tauri.app/security/capabilities/)
生产 CSP 禁止任意远端脚本；不使用 `dangerouslySetInnerHTML` 渲染未清洗内容，远程图片默认不自动加载。
Markdown 禁止脚本、事件属性和危险 URL；本地资源读取只允许当前 skill revision 范围内，外部链接经浏览器打开。
目录选择形成明确的库和项目授权范围；扫描、导入、安装和删除分别验证，防止未注册路径通过 IPC 绕过。
执行写入前重新校验父目录与入口类型，必要时使用平台文件句柄确认身份，减少链接替换竞态。
密钥只在 Rust 侧使用，不回传前端、不进入 URL、日志、锁文件或 Git；日志脱敏并提供手动清除。
备份与日志有保留期限和容量上限；删除库内 revision 必须确认无绑定、无待恢复操作引用。
应用不运行下载内容，但安装后 Agent 可能执行 skill 指令；因此安装预览突出脚本、网络要求和重要内容变更。

## 11. 测试与验收

测试分为业务单元、临时目录集成、桌面端到端、真实 Agent 和发行安装五层，不以其中一层替代其他层。
新增测试围绕不可逆风险与关键行为，不为静态占位页面写镜像式测试。

- **路径与发现**：中文/空格/长路径、大小写冲突、跨卷、Git worktree、嵌套项目、断链、链接循环、权限不足。
- **技能解析**：合法/非法 frontmatter、未知字段、缺 `SKILL.md`、同名来源、相对附件和超限文件。
- **部署恢复**：符号链接/junction/复制三模式；两项目绑定不同版本；升级失败和进程终止后的恢复；卸载保留库内容。
- **外部改动**：复制文件被编辑、受管理入口被替换、父目录成为链接、库内容漂移，均不能自动覆盖或越界删除。
- **下载**：固定 commit、取消、超时、429、重定向凭据泄漏、Zip Slip、链接条目、归档炸弹、重复/大小写碰撞。
- **翻译**：代码/占位符保持原样、缓存命中/失效、密钥脱敏、限流取消、离线回退、原文件哈希不变。
- **迁移**：旧 schema 升级、备份恢复、DB 丢失重建库索引、库迁移后绑定恢复、锁文件异机重建。
- **真实工具**：记录工具版本、操作系统、模式与刷新动作，实际证明技能可发现/可调用，不能以文件存在推定成功。

前端单元/组件测试使用 Vitest；跨进程验证采用 Tauri WebDriver 可支持的平台。
Tauri 官方说明桌面 WebDriver 支持 Windows/Linux，macOS 缺少相应 WKWebView 驱动，因此安排原生手动冒烟测试。[Tauri WebDriver](https://v2.tauri.app/develop/tests/webdriver/)
CI 建议执行前端类型检查/构建、Rust format/clippy/test 和三平台编译；发行安装测试使用独立干净用户配置。
首版性能目标：100 个项目、1,000 个 skills 的已索引检索在基准机器上 P95 小于 300 ms；扫描可取消且 UI 不冻结。
该数字是待测验收目标，必须记录硬件、数据规模、冷/热缓存，不作为当前性能声明。

## 12. 分阶段实施与交付顺序

### P0：当前初始化

交付官方 Tauri 2 + React/TypeScript 基础工程、pnpm 锁文件、MIT 协议、Git、开发辅助 skills 与本文。
只保留工程启动页面，不添加“看起来已可用”的业务按钮；记录实际运行的检查及尚未验证的原生构建条件。
GitHub 公开仓库使用已确认的 `Candquarzy/Askills`；远端是否已创建/推送以 README 和执行结果为准。

### P1：本地技能库与只读项目扫描

完成 SQLite 迁移、库初始化、本地导入/摘要、Markdown 原文阅读器、项目注册与 Codex/Cursor 只读扫描。
先确定 skill 与部署实体、标准化错误、目录身份策略和测试 fixture，再连页面，保持业务与 WebView 解耦。
验收：无网络启动，导入不会改原目录；可准确区分外部技能/断链/冲突，中文路径扫描可取消。

### P2：安全安装与项目绑定

完成计划预览、三种部署模式、锁文件、项目级锁、操作日志、升级回滚和启动恢复。
先用临时目录测试复现所有破坏性失败，再接入界面；逐个完成 Codex、Cursor 实机技能发现验证。
验收：两个项目固定不同 revision；单项目升级不影响另一个；卸载不删除库/用户内容；断电式中断可恢复。

### P3：GitHub 来源与版本管理

完成公共仓库 URL 导入、候选识别、commit 锁定、归档边界、来源许可证展示、更新差异与多项目选择升级。
同时增加 Claude Code 适配和共享路径影响展示，避免新增适配器破坏既有绑定模型。
验收：可从固定 commit 重现相同内容；恶意归档无越界写入；失败下载不出现“已安装”；旧 revision 可回滚。

### P4：中文阅读辅助

完成语言资源、兼容 API 与 Ollama 配置、密钥存储、结构化翻译、缓存、对照阅读和取消/重试。
验收：不改任何原文，外部服务发送范围清楚，离线仍可浏览缓存；代码块/路径/变量与原文逐项一致。

### P5：首个公开可用版本

完善 Windows 安装/升级/卸载测试、无开发者模式降级、错误恢复、导出备份与基本无障碍。
建立 GitHub Actions 检查与 Release 草稿流程；安装包、校验值、许可证和已知限制随版本发布。
macOS/Linux 先做构建与实际链接/权限测试，完成各平台验收后再声明正式支持；签名与公证单独落实。
应用自动更新、私有来源、更多 Agent、团队清单同步随后按需求进入里程碑，不提前混入首版。

每阶段直接向 `main` 提交并推送一组范围清楚的提交，记录行为说明、失败边界、测试证据和待验证平台；日常开发无需 PR。
实现顺序依赖为 P0 → P1 → P2 → P3 → P4 → P5；翻译服务原型可在 P2 稳定后独立推进。
建议每阶段完成后用实际数据校正下一阶段范围，暂不把未验证的工作量写成固定交付日期。
